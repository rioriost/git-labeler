# git-labeler 0.2.1

Reliability fixes for repository classification, daemon coordination, configuration, label clearing, and macOS packaging.

- Bound Git execution with a timeout and drain stdout/stderr without pipe deadlocks. Report operational failures instead of treating them as non-repositories.
- Include untracked files regardless of Git's display settings.
- Serialize event-driven and periodic scans, and deliver events correctly for nested monitoring roots.
- Validate configuration versions, intervals, executable paths, and tag names before use.
- Return unsuccessful CLI exit statuses for scanning or clearing failures. Keep roots configured when clearing fails so the operation can be retried.
- Clear labels using repository identity checks without requiring `git status`.
- Prevent label clearing while a daemon is running with an exclusive service lock.
- Stage package artifacts without deleting unrelated output files or previous releases.
- Add Swift, isolated CLI, and packaging regression coverage through `make check`.

## Upgrade and operation

Stop the existing LaunchAgent before upgrading, then restart it after installation:

```sh
/opt/homebrew/share/git-labeler/scripts/uninstall-launchagent.sh
brew upgrade --cask git-labeler
/opt/homebrew/share/git-labeler/scripts/install-launchagent.sh
```

Always stop the LaunchAgent or foreground daemon before using `config remove PATH --clear-labels`. Daemons older than 0.2.1 do not participate in the new service lock.

Configuration format remains version 1. The supported interval ranges are now enforced: debounce 0-60000 milliseconds and periodic rescan 1-86400 seconds.

Apple Silicon and macOS 13 or later remain supported.
